<context>
You are an expert at solving ARC-AGI (Abstraction and Reasoning Corpus) puzzles using Answer Set Programming (ASP).

ARC-AGI puzzles show input-output grid transformations. Each cell contains a color value (integer 0–9). The goal is to discover the hidden transformation rule from training examples and encode it as an ASP program.
</context>

<rules>
- `input(row, col, color)` facts are injected automatically — do not define them.
- `color(0..9)` facts are injected automatically — do not define them.
- the output predicate is always `output(row, col, color)` — do not redefine it.
- the final program must produce exactly one answer set, in which `output(row, col, color)` match the expected output exactly.
</rules>

<clingo_syntax_reference>

### 1. Rule Structure
Every statement must end with `.`. Three legal forms:
  Fact:       pred(t1,...,tn).
  Rule:       head :- body.
  Constraint: :- body.
Only ONE `:-` per statement — `head :- body1 :- body2` is invalid.
Bare comma-separated atoms without `:-` are invalid:
  Wrong:   input(R, C, V), V != 0.
  Correct: :- input(R, C, V), V != 0.

### 2. Aggregates and Choice Rules
Aggregates use braces `{ }`, never parentheses `( )`:
  Correct:   val(N) :- N = #count{ R : input(R, _, _) }.
  Wrong:     val(N) :- N = #count( R : input(R, _, _) ).

Aggregates always go on the RIGHT side of `=` in an assignment.
As a standalone fact the left side is forbidden:
  Correct:   val(N) :- N = #min{ R : input(R, _, _) }.
  Wrong:     #min{ R : input(R, _, _) } = N.     % aggregate on left of = as a fact

Available aggregates: #count, #sum, #min, #max.

Choice rules guess values within bounds:
  Syntax:   l { atom : condition } u
  Example:  1 { output(R, C, Color) : color(Color) } 1 :- output_cell(R, C).

CRITICAL: `{ }` contains exactly ONE atom (optionally followed by `: condition`).
Multiple comma-separated atoms inside `{ }` is illegal:
  Wrong:     1 { R1, C1, V1, R2, C2, V2 : ... } 1
  Correct:   { chosen(R1,C1,V1,R2,C2,V2) : ... }    % wrap into a single predicate

The terminating `.` goes AFTER the closing `}`, never inside:
  Wrong:     val(N) :- N = #count{ R : input(R, C, V), V != 0.}   % `.` inside braces
  Correct:   val(N) :- N = #count{ R : input(R, C, V), V != 0 }.

Conditions after `:` must be predicate literals, never bare constants:
  Wrong:     1 { pattern : 0 } 1      % 0 is a number, not a predicate
  Correct:   1 { pattern : eq(X, 0) } 1   % or use a boolean predicate

### 3. Arithmetic
Modulo is `\`, NOT `#mod`:
  Correct:   (C + L) \ 2 = 0.
  Wrong:     (C + L) #mod 2 = 0.

Operators: +  -  *  /  \  **  |...|

Arithmetic does NOT bind variables. Every variable in an arithmetic expression
must already be grounded by a positive literal elsewhere in the rule body.

### 4. Safety
Every variable must appear in at least one positive (non-negated) predicate in
the rule body. The following do NOT bind variables:
  - `not` (negation)
  - `=`, `!=`, `<`, `>`, `<=`, `>=` (comparisons)
  - `+`, `-`, `*`, `/`, `\`, `**` (arithmetic)
  - Everything inside `{ }` aggregate or choice braces (Section 6)

Safe example:
  :- input(R, C, V), V != 0, output(R, C, W), W != V.
  % R, C, V bound by input/3; W bound by output/3.

CRITICAL: `not` negates a SINGLE literal, not a parenthesized group.
  Wrong:     :- not (output(R1,C1,V1), input(I,J,V1), used(I,J,R1,C1)).
  Correct:   :- not output(R1,C1,V1).
  (Use separate constraints; `not (a, b, c)` is not valid Clingo.)

Common unsafe patterns and how to fix them:

  1. Variable appears only inside an aggregate:
     Unsafe: rank(R, Rank) :- Rank = #count{X : input(X,C,V), V > R}.
             % R appears only in "V > R" inside the aggregate.
     Safe:   rank(R, Rank) :- input(R,_,_), Rank = #count{X : input(X,C,V), V > R}.

  2. Variable appears only in a choice head (`{ }`), not in the body:
     Unsafe: 1 { pair(R1,C1,V1,R2,C2,V2) : true } 1 :- true.
     Safe:   1 { pair(R1,C1,V1,R2,C2,V2) : input(R1,C1,V1), input(R2,C2,V2) } 1.

  3. Variable bound only by `=`, not by a positive predicate:
     Unsafe: allowed(R, C, Color) :- row(R), col(C), Color = V1.
             % V1 is not bound by any predicate.
     Safe:   allowed(R, C, Color) :- condition(C, V1), row(R), col(C), Color = V1.

  4. Variable appears only in arithmetic:
     Unsafe: zero_cell(R,C) :- N - CountC > R, row(R), col(C).
             % N and CountC only appear in arithmetic.
     Safe:   zero_cell(R,C) :- n_rows(N), colCount(C, CountC),
             N - CountC > R, row(R), col(C).
             % N bound by n_rows/1, CountC bound by colCount/2.

### 5. Comparison Predicates
=  !=  <  <=  >  >=
These test values but do NOT bind variables. Variables on both sides must
already be bound by positive literals elsewhere in the rule body.

### 6. Conditions and Conditional Literals
Syntax:  L0 : L1, ..., Ln
ALL variables to the right of `:` are LOCAL to the aggregate — they do NOT
count as positive bindings for the outside of the rule. This includes variables
in condition literals, not just the element term. For example:
  #count{ R : input(R, C, V), V != 0 }
  R, C, and V are ALL local here.  You MUST bind C and V outside the aggregate:
  Unsafe: colCount(C, N) :- N = #count{R : input(R, C, Color), Color != 0}.
          % C and Color appear only inside — unsafe.
  Safe:   colCount(C, N) :- row(_), col(C), 
          N = #count{R : input(R, C, Color), Color != 0}.
          % col(C) binds C outside the aggregate.

### 7. #show
Add `#show output/3.` at the end of your program. This hides auxiliary
predicates from the answer set, so only output cells appear in the result.

</clingo_syntax_reference>

<asp>
% Grid dimensions
n_rows(N) :- N = #count{ R : input(R, _, _) }.
n_cols(N) :- N = #count{ C : input(_, C, _) }.
row(0..N-1) :- n_rows(N).
col(0..M-1) :- n_cols(M).

% Output has the same dimensions as the input
output_cell(R, C) :- row(R), col(C).

% Each output cell gets exactly one color
1 { output(R, C, Color) : color(Color) } 1 :- output_cell(R, C).

% Copy each input cell to the output unchanged
output(R, C, Color) :- input(R, C, Color).

#show output/3.
</asp>
</example>
