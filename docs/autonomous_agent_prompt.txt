3. PRIMARY HYPOTHESIS: AGENTIC REFINEMENT LOOP
--------------------------------------------------------------------------------

Build a refinement loop that turns a one-shot translator into a back-and-forth
debugger. Concept (proven valuable in `../asp-arc/` — see §8):

For each candidate that fails:
  Round k = 1 .. MAX_REFINEMENT_ATTEMPTS  (default = 2):
    1. Pick the FIRST failed input/output pair for this candidate.
       Do not dump all ~30 failures into the prompt.
    2. Categorize that failure as one of:
         a. Syntax / grounder / compilation error
         b. UNSAT (over-constrained)
         c. Multiple answer sets (under-constrained)
         d. Unique answer set but wrong cells
    3. Build a feedback message:
         - Echo the candidate's program WITH LINE NUMBERS.
         - Include the failure category and the raw Clingo error/output.
         - For (d), include a compact GRID DIFF: expected vs. actual,
           highlighting the deviating cells (row, col, expected, got).
         - Preserve the prior conversation turns so the model has the full
           history of what it has already tried.
    4. Ask the model to produce a fixed program in a single ```asp``` block.
    5. Re-validate.

**Early-stopping per puzzle:** once any candidate for a puzzle passes, stop
refining the OTHER candidates for that puzzle — the puzzle is solved.

**Persist everything:** every refinement round (prompt, thinking, response,
extracted program, validation result, error category, diff) must be appended
to the puzzle's JSONL record. Save more, not less. Disk is cheap; lost runs
are expensive.

Useful one-liners (use `jq`):
  # Per-puzzle pass: any candidate passed?
  jq -s 'group_by(.puzzle_name1+"|"+.puzzle_name2+"|"+(.sid|tostring))
         | map({puzzle: .[0].puzzle_name1,
                solved: (any(.[]; .validation.passed == true))})'
       outputs/batch_<JOB_ID>.jsonl

  # Per-candidate pass rate
  jq -s '[.[] | select(.validation != null)]
         | (map(select(.validation.passed)) | length) as $p
         | length as $t
         | {pass: $p, total: $t, rate: ($p/$t)}'
       outputs/batch_<JOB_ID>.jsonl

      "feedback_prompt": "...",       // exact text sent back to model
      "thinking": "...",
      "response": "...",
      "asp_code": "...",
      "validation": { ... same shape as top-level ... },
      "grid_diff": [ {row,col,expected,got}, ... ]   // only when wrong_cells
    },
    { "round": 2, ... }
  ],
  "final_validation": { ... },         // result after last attempted round
  "solved_at_round": 0|1|2|null        // null if never solved

This makes ablations trivial: you can compute "solved at round 0" (initial),
"solved by round 1", "solved by round 2", etc., directly from the JSONL.

8. PRIOR WORK — `../asp-arc/` (RAID THIS SHAMELESSLY)
--------------------------------------------------------------------------------

Path: `/home/dlindberg/Projects/asp-arc/` (also reachable as
`../asp-arc/` from the repo root).

It implements an agentic refinement pipeline for a different problem
(grids → ASP), but the loop machinery is directly reusable:

- `agent.py`            — syntax-fix agent with `run_clingo` + `edit_code` tools
- `pipeline.py`         — orchestrates initial gen → syntax fix → refinement
- `tools.py`            — tool definitions / parsers
- `eval.py`             — Clingo evaluation, grid-diff utilities
- `main.py`             — full pipeline glue
- `prompts/`            — prompt templates including refinement feedback

Read these BEFORE writing your own loop. Reuse abstractions where they fit;
adapt the prompts to this repo's direction (Python solution → ASP, not
grids → ASP).

Lessons already paid for over there (see project memory):
- Multi-candidate (6) + per-candidate syntax-fix outperformed single shot.
- Syntax-fix loop, even when not fully converged, makes downstream refinement
  succeed where it would otherwise fail.
- Tool-based `edit_code` works well only with old_str/new_str patches;
  full-content rewrites empirically destroy program logic.
- Whitespace/Unicode mismatches silently break `old_str` patching — guard for it.
- `MAX_SYNTAX_ATTEMPTS = 6` was sometimes insufficient.
- Model wastes rounds re-testing known errors — discourage in the prompt.
