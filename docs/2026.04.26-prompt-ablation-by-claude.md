# Prompt-guide ablation: V0 / V1 / V2 across 3 seeds

**Date:** 2026-04-26
**Author:** Claude Opus 4.7 (claude-code session)
**Branch:** `feature/prompt-syntax`
**Predecessor docs:** `docs.improving_prompt_with_syntax_guide.md` (deepseek-v4 session), `2026.04.26-status-by-claude.md`, `2026.04.26-status-by-deepseek.md`.

## TL;DR

- Stripping content from the syntax guide does **not** lower total clingo failures. It **shifts** where the model fails: V1/V2 cut unsafe-variable errors nearly in half, but parse-level syntax errors almost double.
- V0 (the current 221-line guide) had the highest solve rate (2/60 vs 0/60 for V1, 1/60 for V2). Marginal at n=3 seeds but consistent with the error-mix shift: V0 produces 7× more "wrong values" (programs that parse and run, then are semantically off) — those are the only attempts that ever reach the refinement layer.
- Deepseek-v4's reported R1→R3 regression (475 → 635 → 889 unsafe errors) was almost entirely a counting-method artifact. At the (puzzle × attempt × train-example) granularity, R1/R2/R3 sit at 215/218/216 — indistinguishable.
- The dominant failure mode across **all** variants is bare parse-level syntax (`#mod`, `//`, `?:`, missing `.`, aggregate-on-left), not unsafe variables. Deepseek-v4 spent three rounds on safety while parse errors were the bigger pile the whole time.
- Three "Correct:" examples in V0 itself don't compile standalone (lines 53, 57, 79).
- **Recommendation:** stop tuning the syntax guide by adding/removing prose. Move to deterministic regex repair (port `quick_syntax_fix()` from `feature/agentic-nemotron`) and/or refinement-prompt surgery. The lever isn't in the system prompt's guide section.

## Variants

### V0 — control (`prompts/initial_prompt.txt`)

The post-R3 syntax guide deepseek-v4 left in place. Sections 1–7: rule structure, aggregates, arithmetic, safety (with 4 numbered Unsafe/Safe pairs), comparison predicates, conditional literals, `#show`. One worked `<asp>` example (copy-input).

### V1 — minimal cheat-sheet (`prompts/initial_prompt_v1_minimal.txt`)

All Wrong/Unsafe/Safe pairs removed. Replaced with a short `<clingo_essentials>` block: rule forms, aggregates use `{}`, `\` is modulo, the safety rule (no examples), `#show output/3.`. Same single worked example as V0. Tests deepseek-v4's end-of-session hypothesis that "showing wrong examples leaks bad syntax."

### V2 — examples-only (`prompts/initial_prompt_v2_examples.txt`)

Entire `<clingo_syntax_reference>` block removed. Three worked examples:
1. Copy input to output (existing).
2. Recolor every non-zero cell to 5; zeros stay (new — verified single answer set).
3. Mirror left-to-right (new — verified single answer set).

A short "useful patterns" bulleted reminder remains (choice rule, derivation, constraint, safety rule, `#show`). No grammar prose.

## Snippet validation of V0 (preliminary)

Before running ablations, every code snippet inside V0's
`<clingo_syntax_reference>` was parsed + grounded + solved through Clingo
5.6 with a small harness providing `input/3`, `color/1`, etc.

- 33 testable snippets extracted (32 from the guide + 1 worked example).
- 7 skipped as pseudo-syntax templates (e.g. `pred(t1,...,tn).`, `head :- body.`).
- 23/26 testable snippets agreed with their label.
- **3 mismatches**, all "Correct:" examples that fail standalone:

| Line | Snippet | Failure |
|---|---|---|
| 53 | `1 { pattern : eq(X, 0) } 1` | parse: missing `.`; `pattern` undefined |
| 57 | `(C + L) \ 2 = 0.` | ground: `C, L` unbound |
| 79 | `:- not output(R1,C1,V1).` | ground: `R1, C1, V1` only under `not` |

If the LLM lifts these verbatim it produces unsafe-variable errors — the
exact failure category these examples are nominally teaching against.
Suggested complete-rule rewrites are in `experiments/snippet_validation_report.md`.

The R3 fix to **Section 6** (the "C and Color are local to aggregate"
rewrite) was independently verified correct.

## Reading the numbers

### 1. The guide trades unsafe errors for parse errors at near-constant total

The biggest single signal in this experiment. Removing the safety section
(V1, V2) cuts unsafe-variable errors by ~50% (119 → 62/64) but parse-level
syntax errors nearly double (82 → 151/153). Total clingo failures move
only ~13% (209 → 230/236), well within the run-to-run variance band of
±22.

Interpretation: when the safety section is present, the model spends some
of its capacity on rule shapes that obey safety but are otherwise
brittle. When the section is removed, that capacity migrates to other
common-sense Clingo errors — wrong operator names, aggregate-on-left,
missing punctuation. The total error budget appears roughly conserved.

This contradicts deepseek-v4's late-session hypothesis that "showing
wrong examples leaks bad syntax." The guide doesn't seem to be inducing
unsafe errors — it's *shifting* them to parse errors.

### 2. V0 has the highest solve rate, and it's not just luck

V0 solved 2/60 (puzzle, seed) cells. V2 solved 1/60. V1 solved 0/60. At
n=3 seeds this is marginal, but it tracks a more reliable signal:
**V0 produces 7× more "wrong values" results than V1** (21 ± 9 vs
3 ± 3). "Wrong values" means the program parsed, grounded, solved, and
returned an output grid that just didn't match. Those are the only
programs that get useful semantic feedback in the refinement loop.
V1's near-zero wrong_values means it almost never escapes the
syntax-error wall, even after 3 reattempts.

So while the total error count is similar, V0 has more attempts in the
"can be improved" regime. The downstream effect is more solves.

### 3. Deepseek-v4's R1 → R2 → R3 regression was a metric artifact

Re-tallying deepseek's own audits with the (puzzle × attempt × example)
metric:

| Run | Reported unsafe | Per-attempt clingo errors | Per-attempt unsafe |
|---|---|---|---|
| R1 (20260426_111254) | 475 | 215 | 65 |
| R2 (20260426_123318) | 635 | 218 | 70 |
| R3 (20260426_152938) | 889 | 216 | 66 |

The reported "475 → 889" trajectory came from counting per-clingo-log-line.
Clingo emits one "is unsafe" note per unbound variable, so a rule like
`:- N - CountC > R, ... ` with three unbound vars contributes three lines.
Longer programs with more vars-per-rule register as worse without any
attempt-level change. At the unit-of-failure level, R1/R2/R3 are
indistinguishable (within 1.5%).

This means the three rounds of guide tuning, judged by the metric that
actually matters (does this attempt fail or not), produced essentially
no change. The whole "the safety fixes made things worse" finale was
chasing noise.

### 4. Parse errors, not safety, are the dominant failure mode

Across all variants, parse/syntax errors land in the 76–180 range while
unsafe-variable errors land in the 49–130 range. Even on V0 (the variant
with the *most* unsafe errors), parse errors aren't far behind. On V1/V2
they dominate 2–3×.

The deepseek-v4 session spent all three rounds on the safety section.
The intervention with the most expected-value upside was on the
parse-error pile the whole time.

### 5. V1 produces hugely variable program lengths

V1's mean program length is 4070 ± 2094 chars, vs. V0's 1553 ± 77 and
V2's 1744 ± 238. Without the structuring framework of the worked example
+ guide, V1 sometimes induces a "more is more" mode where the model
produces sprawling programs (often empty in extreme cases — 5/240
empty for V1 vs. 1.7 for V0). Worth noting if a future variant goes
even more minimal.

## Methodology notes

### Variance is large enough to wash out 10% effects

Run-to-run stdev on total clingo errors is ±22 against means of ~210.
That's ~10%. With n=3 seeds per variant, the standard error of the
mean is ~13. So a real effect smaller than ~25 (12%) won't be visible
at >1σ. Deepseek-v4 was reading 5–10% deltas on a single run and
calling them regressions.

### What's still worth doing on the guide itself

The 3 "Correct:" examples on lines 53, 57, 79 are unambiguous bugs.
They should be patched (suggested rewrites in
`experiments/snippet_validation_report.md`). Whether that moves the
solve rate is doubtful, but it's a strict improvement and cheap.

### What this experiment did NOT test

- Refinement-prompt content (`reattempt.txt`). Currently has no syntax
  guidance. 82% of refinement transitions stay `clingo_error → clingo_error`.
- Multi-candidate generation (best-of-N).
- Deterministic regex syntax repair before Clingo runs.
- Lower temperature.
- Constraint on reasoning-token budget (might explain the empty-program rate).
- Larger puzzle sets — at 20 puzzles, solve rate variance dominates.

## Recommendations for the next round

1. **Move the lever off the syntax guide.** Three rounds of additions
   (R1→R3) and one round of removals (V0→V1/V2) all produced sub-noise
   movement at the attempt-failure level. The guide is not where the
   bottleneck lives.
2. **Port `quick_syntax_fix()` from `feature/agentic-nemotron`.** A
   handful of regex rules (`#mod`→`\`, `//`→`/`, aggregate-on-left
   swap, ternary stripping, missing periods) would mechanically convert
   a meaningful fraction of the parse-error pile (the 82–153/run) into
   evaluable programs. Costs no LLM tokens. Was never tried on this
   branch.
3. **Patch the 3 V0 snippet bugs.** Cheap; defensible; won't hurt.
4. **Add syntax guidance to the refinement prompt.** It currently has
   none. Even a 3-line "if the previous attempt errored on X, fix it
   like Y" classifier injection could help the 82% stuck-in-clingo-
   error transitions.
5. **Increase n before next ablation.** Either run 50+ puzzles, or use
   5+ seeds, so 10% deltas are detectable. Right now we cannot tell
   whether two prompts differ by anything less than ~25 errors.
6. **Stop trusting per-clingo-log-line counts.** Always tally at the
   (puzzle × attempt × example) granularity. `experiments/compare_runs.py`
   does this correctly.
